# Leren 데이터 저장·활용 구조 결정

## 비교

| 방식 | 복잡도 | 다중 챕터 | 정확도 | 재현율 | 비용·운영 | MVP 판단 |
|---|---|---|---|---|---|---|
| 챕터별 RAG 분리 | 인덱스와 동기화가 늘어남 | 한 청크의 복수 분류가 번거로움 | 범위 제한으로 높일 수 있음 | 챕터 경계에서 누락 위험 | 인덱스 운영 비용 증가 | 초기에는 비추천 |
| 단일 저장소 + 다중 챕터 태그 | 공통 원문·sidecar 관리 | 자연스러움 | policy filter와 review로 조절 | Tutor 검색에 유리 | 한 번 저장·임베딩하고 정책 재사용 | **권장** |
| 문제 생성 자료 직접 제공 | 검색 오류가 적음 | 승인 자료를 챕터별로 관리 | 가장 높은 정밀도 가능 | 검색 재현율과는 별도 | 검수와 prompt token 비용 필요 | 승인된 문제 생성에 사용 |

## 결정

공통 원문·청크 저장소를 기준으로 하고, 청크-챕터 분류 결과와 검수 상태를
sidecar로 관리한다. 문제 생성과 Tutor는 같은 청크 lineage를 사용하되, 다음
접근 정책을 독립적으로 적용한다.

### 문제 생성

`source_review_status=approved`, `license_status=approved`, 챕터 매핑 승인,
근거 구간 존재, `quiz_candidate=true`, Human Review 승인인 경우에만 문제 생성
입력으로 사용한다. 승인된 소수의 청크를 LLM에 직접 제공한다.

### Tutor 검색

출처·권한 검토가 끝난 청크 중 Tutor 허용 정책을 통과한 범위에서 pgvector와
키워드/hybrid 검색을 사용한다. 챕터 태그는 필터 힌트로 활용하되 질문을 과도하게
좁히는 hard filter로 고정하지 않는다. 답변에는 document/chunk ID, URL 또는
locator, hash를 함께 남긴다.

현재 로컬 BOK canonical 데이터는 source URL 789건이 비어 있고, 3,539건 전체의
라이선스 승인 상태가 확인되지 않았으므로 운영 색인·문제 생성 승인을 내리지
않는다. `approved` 값이 없는 현재 스키마에서 임의로 승인 상태를 채우지 않았다.
